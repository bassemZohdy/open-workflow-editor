# Open Workflow Editor — Tasks & Roadmap

> **Status legend:** `[x]` done · `[~]` in progress · `[ ]` pending.
> This file is the source of truth for task status. Update the board as work progresses (see the final section for conventions).

## Goal

Build a real, production-ready "VS Code for Open Workflow Specifications": a browser-based authoring and simulation environment with visual drag-and-drop canvas authoring, complete task property inspectors, bidirectional YAML/JSON synchronization, deterministic auto-layout, schema validation, multi-workflow lifecycle management, and a hardened separation between authoring, simulation, and remote runtime execution — with the IDE-level ergonomics (code editor, command palette, quick open, problems panel, resizable panels, context menus, live status bar) that make it feel like VS Code.

- **Same bug class the project already fixed once (Task 121):** `migration.ts` only scans top-level `document.do`, missing any AI delegation nested inside `try`/`fork.branches`/`switch`. `workflowModel.ts:1006`'s `collectSubflowReferences` already solves this correctly via recursive `visit()` calls — `migration.ts` reimplemented a shallower version instead of reusing it, echoing the exact "each new traversal reinvents the walk" pattern flagged in the 2026-08-23 Tasks 34–57 review.
- **Controller foundation has two latent bugs before any panel uses it (Task 122, 123):** `Controller.dispatch`'s `next === state` no-op check is trivially defeated by an updater that mutates `prev` in place and returns it — reproduced directly, the mutation lands in `getState()` but no listener fires, contradicting the module's own "enforces immutability" docstring claim. Separately, `useController`'s `selector` overload calls the selector fresh on every `getSnapshot()` with no memoization; its own JSDoc recommends passing a selector for "derived/computed slices" — exactly Task 72's planned "derived issue computation" — which is the textbook trigger for React's `useSyncExternalStore` "should be cached to avoid an infinite loop" failure. Zero test coverage on `useController.ts`. Both are worth fixing now, before Tasks 72–79 build six controllers on top of this pattern.
- **Dependency pinning is incomplete (Task 124):** `package-lock.json`'s root manifest block (`packages[""].dependencies`) still declares the pre-fix `"latest"`/`"latest"`/`"^1.0.3-alpha7"` ranges — verified directly — even though `package.json` and the resolved `node_modules/*` entries are correctly pinned. `npm install` (not `ci`) would silently rewrite just those 3 lines; Renovate/Dependabot reading the lockfile's own declared ranges see stale data.
- **`migration.ts` robustness/reuse gaps, no functional bug yet (Task 126, 127, 132, 133):** a skipped rewrite (missing task, malformed workflow target) still gets reported as a successful migration with no diagnostic (126); component matching ignores the delegation's pinned `version`, so a stale sub-flow reference migrates identically to a current one (127); deep-cloning reimplements `JSON.parse(JSON.stringify())` instead of reusing the existing `clone` helper already duplicated 3 times elsewhere (132); and the `path` field on every collected delegation is computed but read nowhere, with a hardcoded form already wrong for nested delegations (133).
- **Controller nits (Task 125, 134):** `dispatch`'s listener loop has no error isolation — one throwing listener silently blocks every listener registered after it (125); `useController`'s two overloads + runtime ternary could collapse to one implementation with a default selector (134, style only).
